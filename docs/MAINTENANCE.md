# 维护与回滚

[返回首页](../README.md)

## 下载历史清理

番剧详情的「下载历史」按单集、合集范围和单片查看记录；全局「下载历史维护」还可查看已删除规则。所选条目会清理同番、同季度、同一集数或范围下的各版本记录。确认后，插件先在线备份 AB 与插件 SQLite，再清除下载历史和去重记录，相关规则暂停等待重新审核。

此操作不删除媒体或下载器任务，但会允许之后再次下载这些集数。`dispatching`／`retry` 等结果不确定的投递不允许强制清除。预览过期或记录发生变化时需重新预览；维护期间暂停相关后台任务，完成或失败后恢复原运行状态，不提供任意 SQL 入口。

同 URL 已有有效下载记录时，插件可备份并清理重复的未匹配孤儿，保留来源关联；不按标题模糊合并。无法确定跨季归属时仍保留未匹配。

## 偏移与过滤变化

「下载版本」读取这部番已收集的候选。后台每 30 秒同步 AB 规则、历史和未匹配种子，完成后可点「刷新版本」查看新候选。预览和确认时核对当前规则和同番的下载历史。标题、季度、组名及偏移等身份字段变化会触发重新审核，保留原始发布标题。

全局和单番过滤分别生效。删掉全局条件不会替你删除单番保留的条件。放宽过滤后，已保存条目会重新匹配；聚合 RSS 未包含的旧发布不会凭空补齐。

## 停用与卸载

暂停单番可停止新投递。若要停用整个插件，先停用 RSS 并停止 AB，恢复普通 qB provider 后再移除插件；否则受控 provider 不存在，AB 无法创建下载器。

在 AB 已停止时，可用安装包中的工具处理实际挂载的配置文件：

```sh
# 仅预览
python3 tools/configure.py /path/to/config/config.json --instance default --restore
# 备份后恢复普通 qB provider
python3 tools/configure.py /path/to/config/config.json --instance default --restore --apply
```

多个 qB 实例重复指定 `--instance`。省略 `--restore` 可离线切换到受控 provider；工具保留实例 ID、连接信息和其他配置，拒绝非 qB 类型。

恢复普通 provider 后，AB 恢复原有自动下载行为。重新启用聚合 RSS 前核对过滤和补集设置。

## 更新与备份

队列位于 `config/plugin-data/subscription-review/review.sqlite3`。保留整个插件数据目录即可保留审核和去重状态；备份 SQLite 时停止 AB 或使用在线备份，不要在运行时只复制主文件而漏掉 WAL。

更新需要 AB 对插件目录及其父目录有写权限，更新暂存与插件目录须在同一文件系统。两份数据库备份在 `backups/<UTC时间>-<ID>/`，旧代码在 `updates/<ID>/previous/`；这些备份不自动清理，可能含站点 URL、令牌和配置凭据，不要公开上传。

新版加载失败时自动恢复旧代码，数据库保留备份，不自动覆盖新数据。断电等进程外中断时，先停止 AB，从 `previous/` 恢复代码，再按需恢复对应数据备份。手动升级时只替换程序文件，保留插件数据目录。
