# AutoBangumi Subscription Review / 订阅审核

适配 **AutoBangumi 4.0.0 + qBittorrent** 的纯插件：Mikan 聚合 RSS 发现新番后，先保存候选，用户选择每部番的版本条件并批准，再自动下载后续匹配的集数。

无需修改或替换 AB 的源文件和镜像。为补足 4.0 的 SDK，本插件在进程内包装下载入口，并注册一个受控 qBittorrent 下载器；内部接口集中在 `review_gate/bridge40.py`。这是针对官方 4.0.0 的兼容实现，不是只依赖稳定 SDK 的插件。

## 功能

- 海报下显示“待选版本 / 追番中”；番剧详情新增原生插槽标签“下载版本”；AB 设置中一键启用。
- 新规则默认待审核；候选独立持久化，RSS 翻页、AB 记录未匹配种子、重启均不丢队列。
- 按字幕组、分辨率、来源、字幕和编码合并候选；每个版本一行，不需要逐集选择或手填关键词。未标注清晰度的发布仍然可选，显示为“清晰度未标注”。
- “必须包含”是逐项 AND，“排除”是任意命中即拒绝；均按字面、忽略大小写，不使用正则。
- 选版本时自动检查匹配集数，点击“开始追番”确认。候选或规则变化会拒绝过期确认，刷新后重新选择。
- 默认“只追后续新发布”，也可选“补下已发现的缺集”；起始集数、排除词和匹配明细收进高级设置。
- 直接选择版本时严格匹配上述五项身份，不把缺失编码或不同字幕组合并放行；高级自定义条件按关键词匹配。
- 导入 AB 已有下载记录；同一番、内容类型、映射季度和集数只接受一个版本，不自动升级 v2 或改下其他编码。
- 下载失败可重试。投递结果不确定时保留该集的原候选占用，阻止另一个版本抢先下载。
- 批准后每 30 秒重试队列，沿用 AB 原有下载路径、`Bangumi` 分类、`ab:<id>` 标签及后续重命名、硬链接、媒体库刷新。

## 0.3.1 下载历史与版本选择

- 下载版本支持多选，命中任一选中版本即可；同时满足多个版本时同一集仍只下载一次。原先保存的单选策略保持兼容。
- 新增“不过滤版本，沿用 AB 规则”：插件不限定字幕组、清晰度和编码；AB 自身排除、其他插件、单集解析和跨版本去重仍生效。
- 同一规则、同一集、同一版本已有 v2/v3 时跳过更低修订；整个 RSS 批次先收集再决策。不会自动替换已下载的 v1。
- 番剧详情新增“下载历史”，设置新增“下载历史维护”（含已删除规则）。按集预览，确认后备份 AB 和插件 SQLite，再清除下载历史、去重标记与已确认投递占用。相关规则暂停等待重新选版本；媒体文件和下载器任务不变。清理不确定的投递（dispatching/retry）会拒绝。
- 两份 SQLite 在线备份在插件数据目录 `backups/<UTC时间>-<随机ID>/`，应用前校验。预览过期或数据变化会拒绝清理。清理时暂停 AB 后台任务，并在完成或失败后恢复原运行状态；不会开放任意 SQL。
- 待审核条目保留番剧关联；后台修复先前留下的已知孤儿。同 URL 的“未匹配、未下载”记录若已有有效已下载记录，会先备份，再补回 RSS 来源并删除重复孤儿。不会按标题模糊合并，也不会删除媒体或 qB 任务。
- 北宇治《上低音号》第三季的标题存在 AB Preview 解析歧义：仅当唯一数字集数括号与经典解析器一致且季数/组名相同，插件采用经典结果修正自己的候选元数据。AB 主程序解析器设置不变。
- 状态改为圆角 badge；版本行展示实际发现的集数。补集仅处理已收集候选，不代表获取了 Mikan 的完整历史。

## 0.4.0 更新与记录同步

- 设置页沿用 AB 原生折叠面板的边框、标题栏、主题色和间距。
- 修改集数/季偏移后，打开版本或历史页及后台每 30 秒同步候选与去重键。原始发布标题保留；相关规则重新审核。不会重命名文件或修改媒体库硬链接。
- 同名跨季匹配优先完整字幕组，仍无法区分季度时保持未匹配。旧的未下载候选有明确完整字幕组匹配时先备份再纠正关联；已下载记录不自动改属。
- 兼容 `【发布组】` 标记；缺少字幕组的候选仍显示为“字幕组未识别”。
- 已入库的未匹配条目会按当前全局和单番过滤重新检查；新关联的旧条目暂停审核，避免取消过滤后直接补下载。全局过滤的修改不会替你删除单番中保留的过滤条件。
- **无需官方签名的一键更新**：首次安装后在 AB 设置 → 订阅审核内使用。启动约一分钟、之后每六小时检查本仓库 GitHub 最新稳定 Release；不会自动安装。点击“更新到…”才下载固定仓库的 ZIP 和 SHA-256 校验文件，校验清单与路径后备份两份数据库及旧代码，暂停后台任务并重载。
- 新版不能启动时恢复旧代码并重载；数据库保留备份供恢复，不会自动用旧快照覆盖期间的新数据。更新后刷新页面。仍需允许未签名本地插件，不改 AB 官方市场验签机制。SHA-256 用于验证下载完整性，不是官方签名。
- 更新备份保存在插件数据目录 `updates/<随机ID>/previous/` 和 `backups/`；只保留源代码备份与数据库，不自动清理。两目录需在同一文件系统，AB 进程需对插件目录及其父目录有写权限。断电等进程外中断需从保留的 previous 目录手动恢复。

## 为什么要切换下载器类型

AB 4.0 的普通 `torrent.filter` 钩子异常时会放行。仅靠该钩子无法保证“未审核绝不下载”。本插件同时提供 `subscription-review-qbittorrent` 下载器：只有同一调用任务中的审核许可才能向真实 qB 发起添加。

插件未加载时，这个 provider 不存在，AB 无法创建下载器；禁用后已经创建的受控客户端也拒绝新添加。它不会回退到普通 qBittorrent。已有 qB 下载和做种任务不受插件阻断新添加的行为影响；插件停用期间 AB 的查询整理可能暂停。

**必须把所有使用中的 qB 下载器实例切换到此类型，保持实例 ID 不变。** 手动在 qB 添加、qB 自己的 RSS 规则、其他应用的下载不受本插件控制。

## 安装与迁移

首次接入会让已有番剧规则也进入待审核；已经下载的文件、qB 任务及 AB 历史不删除。

1. 先停用所有 RSS，保持“番剧补全”关闭，等待当前刷新结束；备份 AB 的 `config` 和 `data`。
2. 把安装包解压到 **`config/plugins/local/subscription-review/`**，目录直接包含 `plugin.toml`、`review_gate/` 和 `web/`。在 AB 设置中允许未签名插件，启用“订阅审核”。
3. 在 **AB 设置 → 订阅审核** 点击 **启用并刷新**。先保存其他未保存的设置。插件会备份配置，仅切换所有 qB 下载器的 provider，保留实例 ID、连接信息及目录，再调用 AB 自身的配置重载。无需脚本或手动重填密码。
4. 看到“已启用”后开启 Mikan 聚合 RSS，旧独立 RSS 先停用保留。所有新发现的番剧先等待选择，不会抢先下载。
5. **点击番剧海报 → 下载版本 → 选一个或多个版本 → 开始追番**。需要补下当前集数时选择“补下已发现的缺集”；已有下载记录自动跳过。历史记录在插件启动及后台同步时自动导入。

首页不再有独立审核面板。海报下的状态用于提示，点击海报打开 AB 原有详情，再进入“下载版本”标签。AB 4.0 的公开 UI 接口不支持从插件状态直接切换原生详情标签。

更新已有安装：停用 RSS 后替换插件目录中的程序文件，重新加载插件并刷新浏览器；保留 `config/plugin-data/subscription-review/`。0.1.0 的已确认策略可继续使用，重新选择一个版本后会使用严格的版本身份匹配。

### 离线切换 provider（备用）

在 **AB 已停止**时，对实际挂载的配置文件操作。脚本只输出实例 ID 和备份路径，不输出凭据。

```sh
# 只预览，不写入
python3 tools/configure.py /path/to/config/config.json --instance default
# 备份后写入；其他设置和凭据原样保留
python3 tools/configure.py /path/to/config/config.json --instance default --apply
```

多个 qB 实例可重复指定 `--instance`。脚本拒绝 aria2 等其他类型。

### 卸载 / 回滚

先停用 RSS 并停止 AB。使用相同脚本追加 `--restore --apply` 恢复原 qB provider，然后再禁用或移除插件。恢复普通 qB 类型会恢复 AB 原本的自动下载行为，重新启用宽泛聚合源前先确认过滤。

插件队列位于 `config/plugin-data/subscription-review/review.sqlite3`（含 WAL 文件）。备份时停止 AB，或使用 SQLite 在线备份；不要在运行时只复制主文件。队列含种子 URL，可能含站点令牌，不要提交到 GitHub。保留该目录可以恢复审批及去重状态。

## 范围与限制

- 严格支持官方 **4.0.0**，版本不匹配拒绝加载。测试基线 commit：`bc23984ae4a6d388c0b8381e48f6aa9b60e338ba`。未来升级 AB 前需先验证兼容层。
- 首版支持可明确识别集数的单集发布。电影、整季合集、无法安全解析的发布保持等待，不会冒险自动下载。
- 去重依赖 AB 历史和插件队列；不是扫描磁盘重建媒体库。只有媒体文件而没有下载记录时，需要明确设置起始集数。AB 既有错误历史也需要先核实。
- 全局排除、单番排除和其他过滤插件仍然生效。被 AB 更早排除、或完全无法匹配任何规则的条目不会进入审核候选。
- 规则名称、季数、组名或偏移等身份字段变化会重新进入审核，避免旧批准被套用到另一部番。
- 不删除媒体、不自动换版本、不自动取消 Mikan 订阅。暂停一部番只停止新投递，已开始的下载不会被取消。
- 不确定的下载失败只重试原候选，不自动切换同集其他版本。当前没有强制覆盖 / 清除单集占用按钮。
- 兼容测试使用 AB 的真实解析、数据库、RSS 引擎、插件加载器和下载门面；外部 qB 网络添加被替身替换。实际 NAS 上的下载和后续整理仍需试用验收。

## NAS 初始化性能

0.2.1 将历史导入合并为单个数据库事务，并明确关闭 SQLite 连接。避免机械硬盘上逐条提交超过 AB 的 30 秒插件启动时限；历史导入完成前不会提供可用的审核下载器。

## 开发与测试

运行时不需要额外 pip 包。开发测试使用官方 AB 的依赖和 Python 3.14。

```sh
git clone --branch 4.0.0 --depth 1 https://github.com/EstrellaXD/Auto_Bangumi.git /tmp/ab-4.0
uv sync --project /tmp/ab-4.0/backend --python 3.14
AB_SOURCE=/tmp/ab-4.0 /tmp/ab-4.0/backend/.venv/bin/python -m pytest -q
PYTHONPATH=/tmp/ab-4.0/backend/src /tmp/ab-4.0/backend/.venv/bin/ab-plugin validate .
python3 tools/build.py
```

`dist/subscription-review-0.3.1.zip` 是允许列表打包的安装包，不含测试状态、凭据、缓存或源码 checkout。CI 针对同一个官方 commit 验证。

## 后续上游方向

插件验证需求后，再向 AB 提议正式的 `defer` 状态、审核后重新投递接口及可选择 fail-closed 的强制关卡，逐步移除对内部下载门面的运行时包装。本仓库不修改 AB 数据库 schema。
